# Mobile Client — Architecture & Status

## Overview

React Native mobile app (Android/iOS) for controlling a remote Okena desktop instance. The Rust
core (`alacritty_terminal` for ANSI processing — identical terminal emulation as the desktop) is
reused below an FFI-agnostic seam and exposed to TypeScript via **uniffi** (a JSI TurboModule
generated by `uniffi-bindgen-react-native`). The terminal grid is painted natively with
`react-native-skia` — **no `xterm.js`, no WebView**. Communicates with the desktop's remote server
over REST + WebSocket.

> Migration note: this app replaced an earlier Flutter + `flutter_rust_bridge` client. The binding
> generator and UI were swapped (`flutter_rust_bridge` → uniffi, Dart widgets → RN components); the
> protocol, TLS, reconnect and ANSI emulation in `okena-core` were reused unchanged. See
> [`mobile/RN_MIGRATION.md`](../../mobile/RN_MIGRATION.md) for the full plan and rationale.

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│ React Native app (TypeScript)            mobile/rn/          │
│                                                             │
│  Screens / navigation / zustand stores                      │

│  TerminalView → react-native-skia <Canvas>  (native GPU)     │
│        │  reads packed cell buffer, 3-pass paint             │
│        ▼                                                     │
│  TS bindings (generated by uniffi-bindgen-react-native, JSI) │
└────────┼────────────────────────────────────────────────────┘
         │  JSI (in-process: sync host fns + Promises)
┌────────▼────────────────────────────────────────────────────┐
│ crates/okena-mobile-ffi   (uniffi-annotated, self-contained) │
│   ConnectionManager (OnceLock + tokio runtime)               │
│    ├─ RemoteClient<MobileConnectionHandler>   (okena-core)    │
│    ├─ MobileConnectionHandler                                │
│    └─ TerminalHolder per terminal → alacritty_terminal::Term │
└────────┼─────────────────────────────────────────────────────┘
         │           HTTP + WebSocket
         ▼
┌─────────────────────────────────────────────────────────────┐
│  Okena Desktop — remote server (okena-remote-server)         │
│  ├── POST /v1/pair       → code → bearer token               │
│  ├── GET  /v1/state      → workspace snapshot (JSON)         │
│  ├── POST /v1/actions    → send_text, split, close, resize…  │
│  └── WS   /v1/stream     → binary PTY frames + state events  │
└─────────────────────────────────────────────────────────────┘
```

## Data Flow

### PTY output (server → mobile screen)

```
Remote PTY → WS binary frame → RemoteClient WS reader (okena-core)
  → MobileConnectionHandler.on_terminal_output()
  → TerminalHolder.process_output(data)          ← alacritty ANSI processing → dirty flag
  → RN render loop (requestAnimationFrame, gated on take_dirty(), which consumes the flag)
  → getVisibleCellsPacked() → ArrayBuffer → decodeCells() → Skia 3-pass paint
```

The hot path uses `get_visible_cells_packed` (a compact `cols,rows` header + 13-byte cells) instead
of marshalling thousands of records per frame across JSI — the key perf lever (Decision C in the
migration plan). The record form `get_visible_cells` is kept for non-hot callers.

Glyphs JetBrains Mono lacks (Claude Code's `⏺ ✻ ✔ ⏵`, braille spinners, emoji, CJK) go through a
per-codepoint fallback (`components/terminalGlyphs.ts`, Skia glue in `terminalFonts.ts`): a few
primary-font aliases (`⎿` → `└`), then the bundled `assets/NotoSansSymbols2-Subset.ttf` (OFL,
loaded by Skia from the JS bundle, not registered for `<Text>`), then the platform fallback
resolved once through SkParagraph. Fallback glyphs are fitted into their cell, or two cells for
wide characters, and the lookups are cached.

### Keyboard input (mobile → server)

```
Soft keyboard / KeyToolbar tap → sendText() / sendSpecialKey() (JSI)
  → ConnectionManager.send_ws_message() → WsClientMessage::SendText → WS → server PTY stdin
```

### State sync (project list, layouts)

```
WS "state_changed" / initial connect → RemoteClient fetches GET /v1/state
  → diff against cached state → create/remove TerminalHolders → state_cache updated
  → RN stores poll getProjects()/getFolders()/getProjectLayoutJson() (1s)
```

### Agent usage (Claude Code / Codex / Grok)

```
WS "usage_changed" → ConnectionManager stores ApiUsage per connection, bumps a revision
  → workspace store poll (1s) calls getUsageRevision(); getUsage() only when it moved
```

The app bar shows one small ring per enabled, signed-in provider (`UsageIndicator`), colored by the
desktop's `max(abs, pace)` severity. While the host routes shells through the AI proxy, the Claude
entry carries the daemon's account pool: the app bar then shows its Today value in its severity
color, and the sheet shows the pool (Today, Nonstop, the daily budget and one row per account with
5h and 7d bars) instead of the login's windows. The daemon computes the pool; the app only formats
it (`buildPoolView` in `src/models/usage.ts`). Tapping it, or Usage in the drawer footer, opens `UsageSheet`,
which calls `requestUsageRefresh` on open (the daemon throttles to once a minute per provider). It
resolves to whether a fetch is running; when it is not (throttled), the spinner ends at once.
`src/models/usage.ts` ports the pace math of `okena-agent-usage::pace`, including the working-day
reshaping of weekly windows, and the desktop popover's display rules, so both clients show the same
numbers (golden tests in `usage.test.ts` and `pace.rs` pin shared values). Codex rows are
titled by window length ("5-hour limit", "Weekly limit") on both clients; Grok rows ("Credits",
"On-demand") keep the desktop's billing-period badge. Times use the phone's clock and zone; clock skew against the daemon is not corrected.

### Presentation: one terminal at a time

The phone does not reproduce the desktop split layout. `WorkspaceScreen` shows only the selected
terminal, full size; when the project has several, a `TerminalTabs` chip row under the app bar
switches between them (layout order, custom name or `Terminal N`). This is client-only: the server
layout, focus and fullscreen state are not changed by switching. Split actions still go to the
server at the path of the terminal on screen (`findTerminalPath`), and the new terminal is
auto-selected. Selection helpers live in `src/models/terminalSelection.ts`.

### Dashboard

A connection opens on `DashboardScreen`, not on a terminal. `dashboardOpen` in the workspace store
switches between it and `WorkspaceScreen`; the workspace app bar's dashboard button and the
Android back button return to it. While the dashboard is open no terminal is on screen, so nothing
is marked seen.

- **Needs you** lists the workspace store's `attention`: every terminal with an open Claude
  dialog, a `blocked` agent, an unseen notification or bell, or a `done` agent not yet seen on the
  phone (`computeAttentionItems` in `src/models/activityOrder.ts`; the same rule drives the drawer's
  attention tier). The state snapshot only counts Claude dialogs, so `claudeDialogsStore` fetches
  the session of each terminal with one while the dashboard is open, to show what it asks. A
  Claude row opens `ClaudeDialogSheet` (answered through `claudeStore`); any other row opens its
  terminal.
- **Pinned projects** lists the projects pinned on the desktop. The phone cannot pin.

### Session restore

`src/state/sessionStore.ts` persists (AsyncStorage key `session_memory`) the server to reconnect to
and, per server, the last project plus the selected terminal of every visited project. On launch
`loadAndRestore` (`src/state/sessionRestore.ts`) reconnects to that server if it is still saved and
paired; the workspace store then reopens the remembered project and terminal, falling back to the
project's first terminal, or opens the project drawer when the project is gone. An explicit
disconnect clears the reconnect target; a dropped connection keeps it.

### Connection resilience

The transport (`okena-transport` `RemoteClient`, shared with desktop) bounds every connect phase:
health check and token check 5 s each, WebSocket dial (TCP + TLS + upgrade) 10 s, auth and state
fetch 10 s each. Host names are resolved and raced across addresses (Happy Eyeballs, 250 ms
stagger). An established session sends `{"type":"ping"}` every 15 s; after 45 s without any
inbound frame it sends a probe and gives up 5 s later, so a socket that died silently reconnects
instead of hanging. A drop re-dials with backoff 1, 2, 4, 8, then 10 s, up to 8 attempts, then
settles in `Error` (the pairing screen's "Try Again").

The FFI reports `Reconnecting { attempt }` separately from `Connecting`. Once a connection has
succeeded (`hasConnected` in `connectionStore`), a drop keeps the workspace on screen with
`ReconnectBanner` ("Retry now" calls `reconnect_now`, which skips the backoff and resets the
attempt budget). The pairing screen's connecting state shows elapsed seconds and offers "Retry
now" after 6 s.

App lifecycle: `App.tsx` forwards `AppState` changes. Android starts a native
`ConnectionService` while connecting, connected or reconnecting. It runs in the app process,
keeping the Rust runtime out of Android's cached-app freezer while the UI is hidden. Its ongoing
notification opens the app and offers Disconnect, which tears down the Rust connection through
the connection store before stopping the service. Pairing, observed terminal errors and explicit
disconnect stop it; removing the app task also stops it. The service is not restarted after process
death.

The service uses `specialUse` with a terminal-session description in the manifest. Google Play
requires a corresponding foreground-service declaration and review for this type. Notification
permission is requested on Android 13+; denial does not prevent the service from running, but
Android then shows it only in the active-apps task manager. No wake lock is held, so Doze and
network changes can still interrupt a connection.

When the Android service is running, going to the background keeps reconnect attempts enabled.
Without a running service (including iOS or a rejected service start), `on_app_background` pauses
reconnect attempts and leaves the established session running. Coming back calls
`on_app_foreground`: a reconnecting connection retries at once with a fresh budget, a `Connecting`
or `Error` one restarts its connect, and a connected one is probed (ping with a 5 s deadline when
nothing arrived for 2 s). Service starts are deferred until the native activity is resumed. React
Native pauses its JS polling timers while the activity is hidden; the Rust socket and keepalive continue independently.
An exhausted reconnect budget is reflected in the service lifecycle when polling resumes.

`init_app` installs a log sink: logcat tag `okena` on Android, unified log subsystem
`com.contember.okena` on iOS. Okena crates log at Info (connect phases with elapsed time, resolved
address, reconnect attempts, ping timeouts), dependencies at Warn. Tokens are never logged.

### Project menus

Both the drawer and compact switcher read the in-memory workspace store; opening them does not
fetch remote state. Their `FlatList` views render a window of rows, including folder headers and
nested worktrees in manual order. Drawer terminal expansion remains part of its project row.
Icons reuse density-sized raster images of their Skia paths through React Native `Image`, with
native tinting; each icon instance does not allocate a Skia canvas.

## Shared Core: okena-core

`crates/okena-core/` contains everything shared between desktop and mobile (reused **unchanged** by
the RN client):

| Module | Contents |
|--------|----------|
| `api` | `StateResponse`, `ApiProject`, `ApiLayoutNode`, `ActionRequest` — serde types |
| `client` | `RemoteClient<H>` state machine, `ConnectionHandler` trait, `ConnectionEvent`, `ConnectionStatus`, `WsClientMessage`, `RemoteConnectionConfig` |
| `client::id` | `make_prefixed_id()`, `strip_prefix()`, `is_remote_terminal()` |
| `client::state` | `diff_states()`, `collect_state_terminal_ids()` |
| `theme::colors` | `ThemeColors`, `DARK_THEME`, `ansi_to_argb()` |
| `keys` | `SpecialKey` enum with `to_bytes()` |
| `types` | `SplitDirection`, `DiffMode`, `FolderColor` |

The `client` feature pulls tokio, reqwest, tokio-tungstenite, async-channel, futures — all with the
**rustls** backends, so the NDK / iOS builds never cross-compile OpenSSL.

Desktop uses the same `RemoteClient<H>` with `DesktopConnectionHandler`; mobile uses
`MobileConnectionHandler` (creates `TerminalHolder` objects in a shared `HashMap`).

## Key Decisions

- **React Native + Rust via uniffi (not RN + xterm.js).** Keep the desktop's exact terminal parser
  (`alacritty_terminal`) and real code reuse via `okena-core`; render natively with
  react-native-skia. The documented fallback if the ubrn build proves too painful is to drop Rust on
  mobile and reuse the web client's TS protocol with a TS ANSI parser feeding the *same* Skia
  renderer — `xterm.js` stays rejected. See `mobile/RN_MIGRATION.md` §5.
- **Self-contained FFI crate.** `okena-mobile-ffi` owns the `ConnectionManager` / `TerminalHolder`
  engine outright (carried over from the retired `mobile/native`, frb attributes stripped). It
  depends only on `okena-core` + uniffi — no Flutter tooling.
- **NoopEventListener on mobile.** The server's `Term` already handles PtyWrite responses; the mobile
  `Term` uses a no-op listener so they aren't written back to the PTY twice.
- **Terminal ID namespacing.** Remote IDs are prefixed `remote:{connection_id}:{terminal_id}`.
- **ConnectionManager as `OnceLock` singleton** with a 2-thread tokio runtime — no GPUI entity system
  on mobile. All FFI functions access it via `ConnectionManager::get()`.
- **FFI `ConnectionStatus`** keeps `Reconnecting { attempt }` distinct from `Connecting`, so a
  once-connected user stays in the workspace while the transport re-dials.
- **DARK_THEME** as the default ANSI → ARGB palette; server-driven theme sync is a later addition.

## FFI Surface (`crates/okena-mobile-ffi/src/lib.rs`)

~60 `#[uniffi::export]` functions. Cheap getters on the render hot path are **sync** JSI host
functions; anything that crosses the wire / awaits a server response is **async** (JS Promise, via
`#[uniffi::export(async_runtime = "tokio")]`). The full contract — and the TypeScript shape ubrn
emits — is mirrored in [`mobile/rn/src/native/okena.ts`](../../mobile/rn/src/native/okena.ts). Highlights:

| Function | Sync/async | Description |
|----------|------------|-------------|
| `init_app()` / `connect()` / `pair()` / `disconnect()` / `connection_status()` | mixed | Connection lifecycle |
| `get_visible_cells_packed(conn, term) → Vec<u8>` | sync | Packed grid buffer — the render hot path |
| `get_visible_cells` / `get_cursor` / `get_scroll_info` / selection getters | sync | Render/selection reads |
| `is_dirty(conn, term) → bool` / `take_dirty(conn, term) → bool` | sync | Changed since last frame (`take_dirty` clears the flag; the render loop uses it) |
| `send_text` / `resize_terminal` / `resize_local` / `scroll` / `send_special_key` | sync | Input / viewport (`send_*` snap the view to the bottom) |
| `scroll_wheel(conn, term, lines, col, row)` | sync | Touch scroll: wheel events in mouse-reporting apps, else local scrollback |
| `get_projects` / `get_folders` / `get_project_order` / `get_project_layout_json` / `get_fullscreen_terminal` | sync | Cached-state reads |
| terminal / git / service / project / layout actions (`create_terminal`, `git_diff`, `start_service`, `add_project`, `update_split_sizes`, `move_pane_to`, …) | async | POST `/v1/actions`, return `()`/JSON |

## Networking

The remote server binds to a configurable IP (default localhost). Mobile clients reach it via:

| Method | Notes |
|--------|-------|
| **Tailscale** (recommended) | Zero-config mesh VPN, free tier, works on mobile |
| **WireGuard** | Manual peer config, low latency |
| **SSH tunnel** | `ssh -L 19100:localhost:19100 server` |
| **LAN** | `--listen 192.168.x.x` to bind to LAN IP |

## Build

```bash
# Rust FFI crate only (runs anywhere — no mobile toolchain needed)
cargo build -p okena-mobile-ffi
cargo test  -p okena-mobile-ffi

# RN TypeScript checks
cd mobile/rn && npm ci && npm run typecheck && npm run lint
```

The native app build (ubrn cross-compile → Android `.so` / iOS xcframework, `pod install`,
`react-native run-*`) requires the mobile toolchain and is documented step-by-step in
`mobile/rn/README.md`. Use `rustls-tls` (already selected by `okena-transport`'s `client` feature) to
avoid cross-compiling OpenSSL for the NDK.
